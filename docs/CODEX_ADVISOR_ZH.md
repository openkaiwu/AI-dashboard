## 界面

- `/` 和 `/codex`：Codex 专属首页，建议优先，其次额度、近 6 小时趋势、重置卡、提醒、Tibo 消息和规则。
- `/connections`：原有采集器配对与撤销功能。
- `/notes`：保留跨端便笺。其他手动 Provider 页面仍保留代码和路径，但退出主要导航。
- Flutter 的 Codex 页面读取同一分析与提醒接口，支持缓存、启停提醒、稍后提醒和忽略。本次不生成 APK。

## 规则定义

| 规则 | 默认触发 | 避免误报 |
|---|---|---|
| 快重置，建议多用 | 剩余至少 35%，距重置不超过 24 小时且处于本周期最后 20% | 其他窗口低于 15% 或已触发慢用时禁止催促 |
| 额度紧张，建议放慢 | 剩余不超过 15%；或距离重置仍远，已用比例比时间进度超前 20 个百分点 | 不把未知时间当成确定周期 |
| 预计提前耗尽 | 有至少 15 分钟同周期样本，剩余量除以近期速度小于剩余等待时间的 70% | 最多观察近 6 小时，计数下降、周期改变、未知字段时截断估计 |
| 重置卡快到期 | API 返回仍可用且已知到期时间，到期不足 24 小时 | 不把未知当作无限期或已过期；不自动兑换 |
| Tibo 重置消息 | 成功检查后 30 小时内、原帖发布 72 小时内 | 带来源与时间；预告不代表本账户已重置；同帖不反复弹窗 |

额度百分比不是 token 数，不推算“还能发多少条消息”。均匀预算是安排任务参考，不保证额度可用性；实际使用仍以 Codex 显示为准。

超过 11 分钟的额度数据暂停节奏提醒。重置时间已过且尚无新周期时不继续推算。采集历史保留 7 天；接口只返回最多 6 小时/500 条用于趋势。重置卡只传数量、哈希后的标识和到期时间，不传兑换所需的原始 ID。

## 提醒行为

- 规则参数按 AI Hub 账户保存，网页和移动端共享。默认 6 小时冷却。
- 相同额度周期、规则、窗口组合只生成一个事件。读取接口与每分钟后台评估并发时通过数据库锁串行，避免重复。
- “1 小时后提醒”在一小时后重新激活；“忽略本次”在此事件周期内保持忽略。
- 默认北京时间 23:00–08:00 免打扰。可改时区和时段；起止相同即不设免打扰。
- 网页站内提醒无需系统权限；桌面通知需用户点击开启，浏览器授权，且网页仍在运行。多标签页通过锁去重。
- 移动端目前是前台刷新和站内提醒；没有后台推送服务。网页关闭或电脑关闭时，不宣称一定送达。

## Tibo / 重置雷达检查（每 3 小时）

当前 Codex 自动任务 `tibo-codex` 应配置为 **每 3 小时** 运行（例如 Cursor Automation `/loop 3h` 或等效 heartbeat）。它读取 @thsottiaux 的公开原帖，核实来源和时间，将白名单摘要原子写入 `.runtime/codex-news.json`，现有电脑采集器自动上传。不会复制 X 登录凭据，不发帖、不点赞。

来源无法访问或近期内容无法确认时写 `unavailable`；不能把检查失败当成没有新闻。相对发布时间会标记 `approximate_time=true`。超过 **3 小时** 未检查会在页面标为过期。首次已读取到的帖子为 https://x.com/thsottiaux/status/2102254445082116335，内容是周二重置预告，未给出具体生效时间；不要据此改写账户重置时间。

检查依赖本机 Codex 自动任务运行环境；不是服务端自带的 X 抓取服务。运行包不会复制这个 Codex 自动任务，迁移机器需重新配置。采集器读取配置文件同目录的 `codex-news.json`，离线或暂停采集时等恢复再上传。

## 验收边界

真实 Codex 接口读到额度和可用重置卡数量（验收时 0 张）；规则触发的临界场景使用可控时间和模拟额度测试，不伪造真实账户额度。已覆盖多窗口冲突、样本不足、重置后的速度截断、未知/过期数据、冷却、跨端稍后/忽略、规则暂停、参数校验及数据隔离。没有为测试消耗重置卡。
