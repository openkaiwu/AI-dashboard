# AIDASH 设备绑定：桌面 ↔ 手机一对一

> 状态：产品规则已锁定 · 2026-09-24  
> 范围：本文只定义绑定与登录门禁；实现需另开变更。不重做公网基建。

## 1. 目标

把「一账号多设备、按 user_id 共享同步流」收成：

- **使用前必须登录账户**
- **桌面端与移动端一对一配对**（每账户最多 1 台活跃桌面 + 1 台活跃手机）
- 同步只在这对已绑定设备之间有效

## 2. 登录门禁

| 客户端 | 未登录 | 已登录且设备有效 |
|--------|--------|------------------|
| 桌面 | 必须先注册/登录；不可使用需账号的同步、额度看板、提醒、bridge 配置下载 | 正常使用 |
| 手机 | 同上 | 正常使用 |
| Web（若保留） | 建议仅作管理台；**不占**桌面/手机 1:1 名额；是否只读另定 | 管理操作 |

Bridge 上报仍可使用 bridge token；但 **创建 bridge / 下载配置** 必须在已登录会话下完成。

## 3. 一对一规则

### 3.1 名额

每个用户账户同时最多：

- **1** 个 `kind=desktop` 且未吊销的设备
- **1** 个 `kind=mobile` 且未吊销的设备

二者构成一对「桌面 ↔ 手机」。

### 3.2 顶号（同类型替换）

- 新 **桌面** 登录成功 → 自动吊销该用户其它未吊销的桌面设备；手机侧保持不变
- 新 **手机** 登录成功 → 自动吊销该用户其它未吊销的手机设备；桌面侧保持不变
- 被吊销设备的 access / refresh token **立即失效**（后续请求 401）

### 3.3 同步范围

- Sync push/pull **仅允许**当前未吊销的桌面或手机会话
- 语义上同步服务于「这对桌面↔手机」；已吊销或未配对设备不得读写
- 不再支持「多台手机 / 多台电脑」同时共享同一用户同步流

### 3.4 与现状对照

| 项 | 现状（实现） | 锁定后 |
|----|--------------|--------|
| 登录建设备 | 每次登录新建 `devices`，可很多台 | 必须登录；同 `kind` 只留 1 台活跃 |
| Sync | `sync_*` 按 `user_id`，多设备互通 | 仅当前活跃桌面 + 活跃手机 |
| 换机 | 旧设备可能仍有效 | 同端新登录 → 旧端立即 401 |
| Bridge | 一账号可多 bridge，与登录设备弱关联 | 配置下载需登录；是否强制 `device_id` 外键可在实现时加严 |

## 4. 建议数据形状（实现提示，非本阶段改库）

- `devices` 增加 `kind`：`desktop` | `mobile`（Web 管理会话可用 `web` 且不占 1:1）
- 登录成功事务内：`UPDATE devices SET revoked_at=now() WHERE user_id=? AND kind=? AND id<>? AND revoked_at IS NULL`
- 可选：部分唯一约束「每用户每 kind 至多一条 `revoked_at IS NULL`」（按数据库能力用 partial unique index）
- Sync 中间件：`CheckDevice` 失败即 401；无需再向已吊销设备投递

## 5. 验收要点（实现后打勾）

- [ ] 桌面/手机无 session 时进入登录页，不能静默使用账号能力
- [ ] 账户下同时最多 1 桌面 + 1 手机活跃
- [ ] 第二台同类型设备登录后，第一台立即 401
- [ ] 异类型互不影响（新手机不踢桌面，新桌面不踢手机）
- [ ] 已吊销设备无法 sync push/pull
- [ ] 未登录不能创建/下载 bridge 配置
- [ ] Web（若有）不占用桌面/手机名额

## 6. 明确不做（本规则文档范围）

- 不在本文阶段改生产代码或迁移
- 不恢复多设备自由同步
- 不把 Web 算进桌面↔手机一对一名额（除非产品另行推翻）
