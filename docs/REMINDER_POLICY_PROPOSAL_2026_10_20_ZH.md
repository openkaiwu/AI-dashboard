# 提醒逻辑优化方案（待实施）

日期：2026-10-20。状态：仅完成当前工作区代码审查与方案编写；未修改程序、运行设置、数据库或服务器，未构建安装包。本方案取代此前允许同一事件因优先级升级、稍后提醒而再次弹出的默认规则。

## 1. 目标与建议默认值

- 桌面默认静默：保留采集、本地统计、页面状态和提醒中心；关闭用量相关系统通知、模态弹窗、抢焦点、任务栏闪烁。普通电脑浏览器也采用静默策略。用户主动进行的登录、安装、操作错误提示不在此次关闭范围内。
- 手机承担主动提醒：后台使用系统通知；前台使用一次轻量提示，不再强制确认模态弹窗。前台和后台共享送达记录，同一事件只选择一种展示方式。
- 相同提醒展示一次后永久保留“已提醒”记录；未读、关闭通知、重启、刷新、同步、重新登录、恢复事件、文案变化或紧急程度变化均不能使它再次弹出。
- 快速消耗必须满足实际消耗严格超过 5 个百分点。“短时间”建议先定义为滚动 15 分钟；这是本方案选定的默认值，用户尚未明确指定分钟数。
- 不追补一串历史弹窗，不因手机离线或权限未开启而回退到桌面弹窗。

| 送达依据设备、事件 ID 和通知时间令牌 | `server/internal/connector/delivery.go`；`apps/desktop/localData.cjs`；手机 `main.dart` 与 `BackgroundSyncJob.kt` | 当前是每设备每一代通知一次，不是整个手机渠道的同一语义事件一次；设备变化或令牌重建存在再次送达路径 |
| “1 小时后提醒”、restore 会重置部分状态 | 桌面 `localData.cjs`、服务端 `connector/advisor.go`、手机 `main.dart` | 与这次“弹出一次就不再提醒”的要求冲突 |
| 临近重置剩余额度建议和外部重置消息通常是页面信息 | `advisor.go` 的 `reset_surplus`、`external_news`；各端过滤 `quota.reset_soon_unused` | 不能笼统认定所有重置消息都在弹窗；应重点消除重置卡分级键，并统一所有重置类出口 |

此外，事件键中包含来源设备及重置时间；重复采集来源或重置时间修正是否造成同一语义事件换键，需要实施阶段用日志核对，当前只列为风险，不能认定为已证实的现场原因。

## 3. 提醒分类与展示规则

| 类型 | 手机主动提醒 | 桌面 | 去重边界 |
| --- | --- | --- | --- |
| 快速消耗 | 满足第 4 节条件时一次 | 页面记录 | 同一提供商账户、额度桶、额度周期最多一次 |
| 额度偏低 | 首次达到现有阈值时一次；已耗尽则只选耗尽 | 页面记录 | 同一额度周期一次；边界波动不重新触发 |
| 额度耗尽 | 首次确认耗尽时一次 | 页面记录 | 同一额度周期一次；与偏低是不同事实，但同批合并 |
| 重置卡到期 | 同一张卡最多一次，建议保留既有提前提醒范围 | 页面记录 | 卡的稳定 ID；不按 1 小时、10 分钟再拆事件 |
| 额度即将重置、已重置、剩余可用额度建议 | 默认不主动提醒 | 页面与雷达 | 只更新记录，不以倒计时变化新建弹窗事件 |
| 外部重置消息、普通建议、采集暂时失败 | 默认不主动提醒 | 页面与雷达 | 信息更新，不进入用量强提醒队列 |

说明：低额度阈值不在本次擅自重设。当前 Codex 默认剩余 15% 的设置与用户已保存配置均沿用。新额度周期允许产生新风险事件，但“进入新周期”本身不弹出重置通知。

## 4. 快速消耗的精确定义

“5 点”指额度百分比的 5 个百分点，不是 token 数、金额、剩余额度的相对 5%，也不是按小时外推的速度。例如已用 30% → 35% 是 5 点，不提醒；30% → 35.1% 是 5.1 点，才达到幅度条件。

建议算法：

1. 按提供商账户、额度桶、主／次窗口、稳定额度周期分组，各窗口独立计算，不把不同窗口的消耗相加。
2. 在当前时刻前 15 分钟内选取有效样本，使用原始精度，不用界面四舍五入值；取窗口内最早与最新有效样本的已用比例之差。不得用超过 15 分钟的起点估计短时消耗。
3. 至少 3 个有效样本，最新样本建议不超过 3 分钟；相邻采集间隔建议不超过 3 分钟。不要求观察满 15 分钟，短于 15 分钟内的真实 >5 点突增也可识别。
4. 数据必须来自同一周期，且可确认计量连续。重置、计数下降、计量口径变化或采集断档时中断计算并重新积累；不跨断档推断快速消耗。
5. `delta_pp > 5.0` 才生成快速消耗候选。`delta_pp <= 5.0`、样本不足、数据过期或周期无法确认均不主动提醒。预测即将用完可以继续显示为页面建议，不能绕过这个门槛。
6. 同一额度周期的快速消耗只提醒一次。随后再下降 5 点、同一峰值滑出又进入计算窗口、优先级变化，都只更新页面。

移动端无需现场凑齐采集样本：由电脑基于完整本地样本计算，并在用户开启同步后上传事件及必要证据（起止时间、前后比例、差值、周期标识）。服务端与手机不得再用另一套门槛重新制造重复事件。远端采集来源也遵循相同规则；需要跨 Go、桌面、Flutter、Android 的共享测试样例保证一致性。

建议文案：“最近 12 分钟额度消耗 5.4 个百分点，当前剩余 42.6%。”不要将短期外推预测写成已确认事实。

## 5. 稳定事件身份与一次性送达

建议统一语义键：`账户范围 + 提供商账户标识 + 额度桶/窗口 + 稳定周期ID + 事件类型`；重置卡使用 `账户范围 + 卡ID + credit_expiry`。区分两个真实账户，同时把同一账户的多个采集设备合并到同一语义来源。

事件键不得包含通知创建时间、轮询时间、当前剩余额度、倒计时、文案或优先级。原始重置时间的轻微修正不能直接产生新周期；“未知重置时间 → 已知重置时间”应关联到已有周期。只有可信周期变化才新建周期；证据不足时保守合并，避免重复打扰。

将“展示送达”与“已读／忽略／当前有效”分开保存：

- `presented_at` 一旦写入不能因未读、restore、恢复网络、同步合并或冷却到期清空。
- 同一手机前台和原生后台共用原子送达入口；按语义键去重，而不是仅按 `notified_at` 令牌。
- 选择一台“主提醒手机”。同账户其他手机默认只同步；更换主手机不重放已经送达的事件。手机渠道的服务端唯一记录用于跨设备兜底，桌面不抢占手机送达资格。
- Codex 提醒与通用通知都进入同一套送达规则，不能只修复其中一个入口。
- 不保留默认“1 小时后提醒”重发入口；“恢复”只恢复列表可见性。若未来要增加用户主动设定的定时提醒，应作为独立功能，不混入本次自动提醒。
- 本地及服务端保存精简去重记录，不能随旧提醒详情的 30 天清理一起删除。重装后先恢复去重状态再启用送达，不能先弹历史消息再拉取记录。

崩溃窗口需要明确取舍：系统通知提交与数据库写入不能构成同一个事务，不能承诺任何故障下数学意义上的“恰好一次”。本方案优先避免重复：持久化发送占位，使用固定系统通知 ID；状态不确定的发送不自动重发，只保留提醒中心记录。测试必须覆盖发送前后进程被杀、回执失败与服务端不可用。

## 6. 限频、合并与过期处理

- 建议手机账号级硬间隔为 30 分钟，优先级不能绕过；此数值是降低打扰的建议默认值。
- 同一轮出现多个窗口／多个原因，生成一条摘要，优先显示耗尽、偏低、快速消耗、卡到期；同一窗口已耗尽时不再单独弹低额度和快速消耗。摘要中实际包含的事件统一记为已提醒。
- 间隔内出现的新事件先只更新列表，到可送达时重新检查，只合并仍有效的事件；绝不按历史发生顺序逐条补发。
- 快速消耗候选有效期建议 15 分钟，超过后只保留历史；额度耗尽／偏低在最新数据证实风险仍存在时可提醒一次。卡已到期或风险解除则不补发。
- 免打扰时段继续生效，结束后同样重新验证。权限被拒绝、数据过期、手机离线时显示状态，不通过桌面替代打扰。

## 7. 手机送达与本地默认保存的关系

当前自动上传默认关闭，Android 原生任务配置为 15 分钟周期。只关闭桌面弹窗并不能让手机获取未同步的数据；需要在设置中给出完整的“手机提醒”开通流程。

建议由用户显式开启“同步到手机并提醒”，界面解释上传范围：额度摘要、判定所需统计及提醒状态，不上传会话正文或登录凭据。本地仍保存完整分析数据；未开启时保持本地模式，并显示“手机提醒未启用”，不能暗中开启全量同步。

手机设置显示主提醒设备、通知权限、通知横幅／声音、后台同步状态、最近成功同步时间；允许用户主动测试一次通知。打开手机前台只更新历史记录，不补弹已发过的提醒。

现有 15 分钟后台轮询不应写成实时推送保证。实施时先验证真实手机的后台调度与厂商省电限制；如果必须低延迟，再另行设计推送通道。所有通道最终共用同一语义去重记录，不能因接入推送多弹一次。

## 9. 验收清单

| 场景 | 预期 |
| --- | --- |
| 电脑采集到耗尽或快速消耗 | 页面更新，无桌面弹窗、声音、闪烁、抢焦点 |
| 手机收到相同事件后反复轮询／打开前台 | 总共只展示一次 |
| 同一卡从 24 小时接近到期到 1 小时、10 分钟 | 最多一次通知，不因等级变化再发 |
| 15 分钟内实际消耗 4.9／5.0／5.1 点 | 前两种不触发；5.1 在样本有效且未送达时触发 |
| 预测提前耗尽，但实际短时消耗只有 2 点 | 页面建议，不发快速消耗通知 |
| 相同周期重复出现多个 >5 点区间 | 快速消耗最多一次 |
| 两个窗口各消耗 3 点 | 不相加成 6 点，不触发 |
| 断网恢复后发现额度下降 8 点，但发生时间不明 | 不认定短时快速消耗 |
| 重置时间修正／未知时间补全／重复采集同一账户 | 不生成第二个相同语义事件 |
| 同时出现低额度、耗尽与快速消耗 | 合并；同一窗口以耗尽为主，不排队连弹 |
| 前台和后台并发、网络回执失败、进程中断 | 不重复发布；不确定发送保留列表记录 |
| 30 分钟内新高优先级事件 | 不绕过硬间隔，按规则重新验证并合并 |
| 通知被关闭、事件未读、restore、重新登录 | 不重新打开已提醒事件的送达资格 |
| 覆盖安装、保留数据重装、更换主手机 | 恢复送达记录后再检查，不重放历史提醒 |
| 手机未授权通知／同步未开启 | 明确显示未启用原因，桌面保持静默 |

实施验收需包含 Android 实体手机后台、锁屏和省电场景；静态审查与模拟器不能代替这部分验证。
