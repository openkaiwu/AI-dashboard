# Codex 额度消耗显示图设计（5h / 1 天 / 1 周 / 1 月）

状态：V1 已实现上线（API 增量 + Web 四面板）；V2 移动端与 V3 可选项未实现。数据口径沿用 `docs/QUOTA_CONSUMPTION_DESIGN_ZH.md`（同代差分、重置不计消耗、无样本留空）。

## 一、四个维度各自回答的问题

| 维度 | 回答的问题 | 数据来源 | 套餐依赖 |
|---|---|---|---|
| **5h** | 这个五小时窗口用了多少？照这个速度何时触顶？ | Codex 原生 5h 窗口实时数据（当前代原始样本） | plus/pro 上报；prolite 不上报 |
| **1 天** | 今天 / 最近 24 小时用了多少？什么时段用得多？ | 小时 rollup（consumed_pp/hour，跨零点滚动 24h + 30 天日历日） | 无（所有套餐） |
| **1 周** | 本周用了多少？比上周多还是少？周窗口还剩多少？ | 日 rollup（近 7 天）+ Codex 原生周窗口实时水平 | 无 |
| **1 月** | 这个月用了多少？趋势如何？ | 日 rollup（近 30 天）+ 月聚合（自部署日起积累） | 无 |

**关键事实**：Codex 原生只有 5h（300 分钟）与 7 天（10080 分钟）两种窗口；"1 天"和"1 月"不是上游窗口，是**派生视图**。原始样本保留 7 天，小时 rollup 保留 400 天——四视图的数据可得性据此分配。

## 二、页面结构（消耗分析 tab 重构）

现粒度切换模式改为**四张固定面板**，纵向滚动一页看全，去掉模式切换的心智负担：

```
┌─ P1 五小时（实时）────────────────────────────────┐
│  剩余 87%                          重置于 23:15    │
│  折线: 本代 used% 曲线 ─ 均匀线 ┄ 预测触顶 ┈        │
│  已运行 2h41m/5h · 速率 8.3pp/h · 预计触顶 22:47    │
│  （prolite：整卡置灰，"Codex 未上报五小时窗口"）      │
├─ P2 一天 ────────────────────────────────────────┤
│  近 24 小时消耗 21.4 pp（大数字）                   │
│  迷你图: 24 根小时柱（跨零点）                      │
│  主图: 30 天日消耗柱 + 均匀参考线 + ▲ 重置          │
│  昨日 12.1pp · 日均 8.7pp · 峰值小时 21 时          │
├─ P3 一周 ────────────────────────────────────────┤
│  近 7 天消耗 43.7 pp（大数字）                      │
│  柱: 7 天日消耗  ·  环比上周 -18% ↓                │
│  周窗口进度条: 已用 4%（与总览周窗口同源）           │
├─ P4 一月 ────────────────────────────────────────┤
│  近 30 天消耗 156 pp（大数字）                      │
│  柱: 30 天日消耗 + 7 日移动均线叠加                 │
│  月度对比（近 3 个日历月小柱图，积累中 N/30 天）      │
└──────────────────────────────────────────────────┘
```

每面板 = 一个大数字 + 一张主图 + 一行统计，纵向锚点可跳转；替代现粒度分段按钮。

## 三、面板详细规格

### P1 五小时（实时窗口）

- **数据**：`GET consumption?granularity=window&window=300` 的当前代原始点（`t, used`）+ 最新快照的 5h 窗口（resets_at / used）。
- **折线**：当前代 used% 随时间；**均匀线**：窗口起点 0% → 重置点 100% 的直线；**预测虚线**：以最近 3 个样本的差分速率外推，与 100% 线的交点即"预计触顶时刻"。
- **大数字**：剩余 = 100 − 最新 used。
- **统计行**：已运行时长（now − 窗口起点，窗口起点 = resets_at − 5h）；当前速率 pp/h；预计触顶时刻（速率 < 0.5pp/h 显示"速率平稳，本轮不会触顶"）；重置倒计时。
- **套餐自适应**：`plan_type` 为 plus/pro → 全量；prolite / 快照无 5h 窗口 → 面板置灰 + 文案"Codex 暂未上报五小时窗口（以 Codex 实际为准）"，其余面板不受影响。

### P2 一天

- **大数字**：滚动 24 小时消耗 = Σ 小时 rollup consumed_pp（hour ≥ now−24h）。
- **迷你图**：24 根小时柱，跨零点（x 轴小时标签，属两日以浅色分隔）。
- **主图**：30 天日历日柱（consumed_pp/日）+ 均匀参考线 + ▲ 重置标记。
- **统计行**：昨日合计、30 天日均、峰值小时（含时刻）、有数据天数。
- **注意**：滚动 24h 与"昨日/今日"日历口径并存展示，避免歧义。

### P3 一周

- **大数字**：近 7 天消耗合计（Σ 日 rollup）。
- **柱**：最近 7 天逐日消耗。
- **周窗口进度**：原生周窗口 used%（与总览卡片同源同值）——明确标注"这是 Codex 周窗口，与'近 7 天消耗'口径不同"。
- **环比**：本日历周（周一起）vs 上周同期，来自服务端 `compare` 字段；数据不足一周时显示"上周同期数据积累中"。

### P4 一月

- **大数字**：近 30 天消耗合计。
- **柱**：30 天日消耗柱 + **7 日移动平均线**叠加（平滑趋势）。
- **月度对比小图**：最近 3 个日历月合计（rollup 自部署日起积累，不足显示"积累中 N/30 天"）。
- **统计行**：30 天日均、峰值日（含日期）、重置次数、覆盖天数。

## 四、API 增量（现有 consumption 端点扩展，无新端点）

| 增量 | 说明 |
|---|---|
| `granularity=hourly&hours=24` | 返回小时序列 `[{hour, consumed_pp, samples, resets}]`（rollup 直读），供 P2 迷你图与滚动合计 |
| `compare=true` | weekly/monthly 响应增加 `compare:{this_pp, prev_pp, ratio}`（服务端周聚合，与 E1 洞察同源） |
| 响应增加 `plan_type` | 前端按套餐禁用/置灰 P1 |
| 现有 `window=300` 过滤 | 已支持，P1 直接复用 |

前端取数：P1 = `granularity=window&window=300`；P2 = `granularity=hourly&hours=24` + `granularity=daily`；P3 = `granularity=daily&days=7` + `granularity=weekly&compare=true`；P4 = `granularity=daily&days=30` + `granularity=monthly`。共 4 类请求，可并行。

## 五、边界与规则

| 边界 | 处理 |
|---|---|
| prolite / 无 5h 上报 | P1 置灰说明；P2/P3/P4 正常（基于已上报消耗的差分） |
| 重置发生在一天中间 | 当日柱 = 同代差分之和 + ▲；重置跳变本身不计消耗 |
| 无样本时段（离线） | 柱缺失留白，tooltip 注明"无样本"，不插值 |
| Codex 侧百分比修正（下降 >2pp） | 记为重置（▲），不计负消耗 |
| 部署后数据积累 | P3/P4 显示"积累中 N 天"；P1/P2 上线即有数据（7 天原始历史回填覆盖） |
| 多设备 | 按桥 rollup 求和（当前 1:1 绑定，无实际影响） |
| 时区 | 全部按账户偏好 utc_offset_minutes 分桶与标注 |

## 七、验收要点

1. plus/pro 账户：P1 实时曲线与总览趋势一致（同数据源）；触顶预测随速率更新；
2. prolite 账户：P1 置灰说明，P2/P3/P4 正常展示；
3. 重置日：P2/P3/P4 当日柱出现 ▲ 且消耗不含跳变；P1 旧代曲线止于重置点、新代重新开始；
4. 断电一天：四面板该日全部空档，P4 移动均线绕过空档；
5. 滚动 24h 大数字与小时柱之和一致（同一数据源）。
